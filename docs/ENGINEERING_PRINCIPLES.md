# Engineering Principles — cactusInv

These principles are how cactusInv is built: hexagonal Go, API-first, container-native,
file- or Vault-backed secrets, a mobile-first React app and one quality gate. cactusInv is a
standalone application with no dependency on any other system. Every deliberate trade-off
is written down here and in an ADR.

`CLAUDE.md` is the short, binding version of this file. `docs/ARCHITECTURE.md` is the
structural detail. `PLAN.md` is what is being built and where we are.

---

## 1. Keep it simple, on purpose

cactusInv is a **simple invoice system** for a small business. The aim is one dependable
binary that a single person can run, not a platform.

- **One binary, one module, one database.** A modular monolith (`cmd/cactusinv`) with
  hexagonal layers inside it. No microservices, no message broker. If a second deployable
  is ever needed, the port boundaries are already where the split would happen
  (ADR-001).
- **Boring technology.** Go standard library first. A dependency is added only when
  writing it ourselves would be worse (PDF rendering, the MariaDB driver, migrations,
  generated API code).
- **No speculative features.** Build what `PLAN.md` asks for. Anything else goes in
  `PLAN.md` → *Later* with a sentence on why it was deferred.

## 2. Correct money, always

Invoices are financial documents. A wrong cent is a bug of the highest severity.

- **Money is `int64` minor units plus an ISO-4217 currency code.** Never `float64`,
  never a decimal string doing arithmetic (ADR-005).
- **Currencies never mix.** Adding a ZAR amount to a USD amount is a domain error, not a
  conversion. There is **no FX conversion** anywhere: a product has an explicit price per
  currency (ADR-003).
- **Rounding is defined once** (`domain.RoundHalfAwayFromZero`) and is applied per line,
  then totals are sums of rounded lines. The worked example from the reference invoice
  (`14 × 192.94 = 2701.16`, `+ 550.00 = 3251.16`) is a permanent unit test.
- **Quantities are fixed-point milli-units** (`int64`, three decimals), so "1.5 hours" is
  exact.
- **Issued invoices are immutable.** After `issue`, lines, totals, number, currency and
  bank details are frozen. Corrections are a `void` plus a new invoice, never an edit.
- **Snapshots, not references, for anything printed.** The invoice stores the bill-to
  address, the bank details and each line's description and price as they were on the
  day. Editing a customer or product later never rewrites history.
- **Invoice numbers are gap-free and unique**, allocated from a row-locked sequence in
  the same transaction that issues the invoice.

## 3. Architecture is a rule, not a suggestion

- **Hexagonal (ports & adapters).**
  `internal/domain` → pure Go, no I/O, no `time.Now()`.
  `internal/app` → use cases, depends only on domain + ports.
  `internal/ports` → interfaces the app needs (repositories, mailer, PDF renderer, clock,
  secrets, transactions).
  `internal/adapters/*` → MariaDB, HTTP, SMTP, PDF, Vault, worker loops.
  `cmd/cactusinv` → the **only** place adapters are wired together.
- **Imports point inward only**: `domain ← app ← ports ← adapters ← cmd`. Enforced by
  `depguard` in `.golangci.yml`.
- **Business rules live in the domain.** Not in SQL, not in HTTP handlers, not in React.
  The frontend renders and submits; the server decides.
- **Use cases own transactions** through a `ports.TxManager`. A use case either fully
  happens or does not happen.

## 4. API-first

- `api/openapi/cactusinv.yaml` is written **before** the handler. Server stubs are
  generated by `oapi-codegen` (strict server); the web client types by
  `openapi-typescript`. Generated code is committed and checked for drift by
  `make contracts`.
- Errors are RFC 9457 `application/problem+json`, mapped from typed domain errors in the
  HTTP adapter only.
- Every mutating `POST` accepts an `Idempotency-Key` header. Retrying "send invoice" must
  never send two e-mails.
- Lists are paginated. The API is versioned by URL prefix `/api/v1`.

## 5. MariaDB is the system of record

- **MariaDB 11 (LTS), InnoDB, `utf8mb4`.** Required by the brief; no Postgres-isms
  (ADR-002).
- **`goose` SQL migrations**, every `Up` has a working `Down`, verified against a fresh
  database by `make migrate-check`. Committed migrations are never edited — write a new
  one.
- **`sqlc`** generates typed query code from hand-written SQL. No ORM.
- **Constraints in the schema too.** Foreign keys, `UNIQUE`, `CHECK` and a generated
  column enforcing "one default bank account per currency". The domain validates first;
  the database is the last line of defence.
- **Concurrency is explicit.** Optimistic locking (`version` column) on editable
  aggregates; `SELECT … FOR UPDATE SKIP LOCKED` for the scheduler and e-mail dispatcher
  so several replicas can run safely.
- All timestamps are stored in **UTC** (`DATETIME(6)`); business dates (`issue_date`,
  `due_date`) are `DATE` in the business time zone.

## 6. Scheduling and e-mail are reliable by construction

- **Transactional outbox for e-mail** (ADR-004). Sending an invoice writes an
  `email_outbox` row in the same transaction as the status change. A dispatcher delivers
  it later with retries and exponential backoff. A crash can delay an e-mail; it can
  never lose one or send one for an invoice that was rolled back.
- **"Send later" is just an outbox row with a future `next_attempt_at`.** One mechanism
  serves "send now", "send on Friday at 09:00" and recurring schedules.
- **Recurring schedules are idempotent per period.** A schedule run is keyed by
  `(schedule_id, period_start)` with a unique constraint, so a retried or concurrent run
  never produces a second invoice for the same month.
- **Time is injected** (`ports.Clock`). Recurrence maths is pure domain code and is
  table-tested across month ends, leap years and time zones.

## 7. Secure by default

- **Secrets come from files** — Docker/Compose secrets or a Kubernetes Secret mounted at
  `/run/secrets` — or optionally from HashiCorp Vault KV v2 (ADR-006). Database and SMTP
  passwords are never in code, images, tests, `.env` or the repository. `deploy.sh`
  generates random database passwords on first install.
- **Default administrator.** A fresh installation creates `admin` / `admin` (configurable in
  `.env`) only when no user exists, and logs a warning. Change it after the first sign-in
  (`cactusinv admin set-password admin`).
- **Authentication**: e-mail + password (argon2id), server-side sessions in an
  `HttpOnly; Secure; SameSite=Strict` cookie, CSRF protection via same-site cookie +
  required custom header on mutations.
- **Never log PII or secrets.** Log IDs (`invoice_id`, `customer_id`), never e-mail
  addresses, bank account numbers or passwords.
- **Validate at the edge, enforce in the domain.** Input is validated by the generated
  OpenAPI layer and again by domain constructors.
- Containers run **distroless, non-root, read-only root filesystem**.

## 8. Mobile-first UI

- **Designed at 360 px wide first**, then enhanced at `sm`/`md`/`lg`. Bottom tab bar on
  phones, side nav on desktop. Lists are cards on phones, tables on wide screens.
- Touch targets ≥ 44 px, forms usable one-handed, numeric keyboards for amounts
  (`inputMode="decimal"`).
- **The React app is a pure API client** (React + TypeScript + Vite + Tailwind). It does no
  money maths that matters: totals shown while editing are a preview; the server's figures
  are the truth.
- Accessible: semantic HTML, labels on every input, visible focus, WCAG AA contrast, light
  and dark themes.
- The built app is embedded in the Go binary (`embed`), so one artifact serves API and UI.

## 9. Operable

- **12-factor**: configuration from environment variables only, parsed into a typed struct
  and validated at start-up.
- **Structured JSON logs** (`log/slog`) to stdout. Prometheus metrics at `/metrics`
  (HTTP RED, outbox depth and age, schedule runs, send failures). `/healthz` (liveness)
  and `/readyz` (DB + Vault).
- **Graceful shutdown** on SIGTERM: stop accepting, finish in-flight requests, let
  workers finish their current item.
- Background workers run inside the same binary and can be disabled per replica
  (`CACTUSINV_WORKERS=false`).

## 10. Deployable anywhere Docker runs

- **One script** — `deploy.sh --install|--uninstall|--delete-uninstall
  --dockerdesktop|--k3s|--k8s [--ssh-access user@host]` (ADR-007). The same image runs on
  Docker Desktop, Docker Engine, k3s and Kubernetes.
- **`.env` holds every default**: host volume mappings (database, invoices, backups,
  secrets), ports, schedules, storage sizes. No secrets.
- **Data outlives the app.** `--uninstall` keeps the database, invoices and backups;
  only `--delete-uninstall` (with confirmation) removes them.
- **Backups are scheduled by default** (daily, retention in days) and restorable with one
  command. Every issued invoice is also exported as a PDF to the invoices volume (ADR-008),
  so the documents survive independently of the database.

## 11. Code quality

- Errors are wrapped with context: `fmt.Errorf("invoice.Issue: %w", err)`. Domain errors
  are typed sentinels in `internal/domain/errors.go`.
- `context.Context` is the first parameter of anything that does I/O.
- No `init()`, no mutable globals, no `panic` outside `main`.
- Every exported symbol has a doc comment. Every use case has a table-driven test.
- One use case per file in `internal/app`.

## 12. Testing

| Layer | How | Bar |
|---|---|---|
| Domain | pure unit tests, table-driven | ≥ 80 % coverage (target 90 %) |
| App | unit tests with hand-written fakes in `ports/fakes` | ≥ 80 % coverage |
| MariaDB adapter | integration tests against real MariaDB 11 via `testcontainers-go` | every repository method |
| HTTP adapter | `httptest` against the generated router with fake use-case deps | every endpoint's happy path + main error mapping |
| PDF | golden-structure test (text extraction of totals, number, bank) | reference invoice reproduced |
| Web | Vitest + Testing Library | lint, typecheck, tests, build |

Tests never hit the network, never sleep on wall-clock time (fake clock), and never need
secrets.

## 13. The quality gate — `make check`

Nothing is "done" unless `make check` is green: `gofumpt`, `golangci-lint`, `go vet`,
unit tests with race detector and coverage thresholds, integration tests, `govulncheck`,
contract drift, migration up/down check, web lint/typecheck/test/build. Gates are never
bypassed with `//nolint`, `t.Skip` or lowered thresholds.

## 14. Process

- `PLAN.md` is the source of truth and is updated **as work happens**; a crashed session
  must be resumable from it alone.
- Decisions go in `PLAN.md → Decisions`; architectural ones get an ADR in `docs/adr/`.
- Conventional commits referencing the plan step: `feat(invoice): gap-free numbering (PLAN 2.3)`.
- Small verified steps: change → check → fix → next.
